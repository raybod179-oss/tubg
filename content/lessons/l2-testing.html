تست‌نویسی (Feature و Unit)

تست یعنی کدی که درستیِ کد دیگرت را خودکار چک می‌کند. با تست، بدون ترس از خراب‌شدن چیزی، پروژه را تغییر می‌دهی.

۱. ساخت و اجرا

Feature تست مسیر کامل درخواست را می‌زند و Unit تست یک کلاس یا تابع کوچک است.

کدartisan
php artisan make:test ProductTest            # Feature
php artisan make:test PriceTest --unit      # Unit
php artisan test

۲. یک Feature test

RefreshDatabase دیتابیس تست را برای هر تست پاک می‌کند و به دیتابیس واقعی دست نمی‌زند.

کدtests/Feature
<?php
use App\Models\{Product, User};
use Illuminate\Foundation\Testing\RefreshDatabase;

class ProductTest extends Tests\TestCase
{
    use RefreshDatabase;

    public function test_products_page_loads(): void
    {
        Product::factory()->count(3)->create();
        $this->get('/products')->assertOk();
    }

    public function test_admin_area_needs_admin(): void
    {
        $user = User::factory()->create();
        $this->actingAs($user)->get('/admin')->assertForbidden();
    }
}

۳. Unit test

بدون دیتابیس و بدون HTTP؛ فقط منطق خالص.

کدtests/Unit
<?php
class PriceTest extends PHPUnit\Framework\TestCase
{
    public function test_discount(): void
    {
        $this->assertSame(180, (int) (200 - 200 * 10 / 100));
    }
}

۴. تمرین

برای فروشگاه دوره تستی بنویس که ثبت سفارش موجودی را کم کند و تستی که نشان دهد مشتری سفارش دیگران را نمی‌بیند (۴۰۳).

اشتباه‌های رایج

  1. نگذاشتن RefreshDatabase و پاک‌شدن داده‌ی واقعی در حالت MySQL.
  2. تست‌نویسی بعد از تمام‌شدن کل پروژه؛ همان لحظه که بخش را می‌نویسی تستش را هم بنویس.
