Service و Repository و کد تمیز

کنترلر باید نازک باشد: درخواست را بگیرد، کار را به کلاس مناسب بدهد و پاسخ بدهد.

۱. Service

منطق کسب‌وکار را از کنترلر بیرون ببر. لاراول خودش وابستگی را تزریق می‌کند.

کدService
class OrderService
{
    public function place(User $user, array $data): Order
    {
        return DB::transaction(function () use ($user, $data) {
            // ساخت سفارش و کم‌کردن موجودی
        });
    }
}

public function store(CheckoutRequest $r, OrderService $orders)
{
    $order = $orders->place($r->user(), $r->validated());
    return redirect()->route('orders.show', $order);
}

۲. Repository چه موقع؟

برای پروژه‌های متوسط Eloquent خودش کافی است. Repository فقط وقتی لازم است که بخواهی منبع داده را عوض کنی یا تست را ساده کنی؛ بی‌دلیل لایه اضافه نکن.

۳. اصول کوتاه

نام‌های گویا، تابع‌های کوتاه با یک مسئولیت، اجتناب از تکرار، و فرمت خودکار با Pint:

کدPint

اشتباه‌های رایج

  1. انتقال همه‌چیز به Repository از روز اول و پیچیده‌شدن بی‌دلیل.
  2. Service بزرگ با ده‌ها متد؛ آن را به کلاس‌های کوچک‌تر بشکن.
