سطح ۲ · درس 10

اتصال درگاه پرداخت

جریان همه‌ی درگاه‌ها یکی است: درخواست پرداخت ← انتقال کاربر به درگاه ← بازگشت ← تأیید (Verify) ← ثبت نهایی.

۱. جریان

اول سفارش با وضعیت pending بساز. بعد از پرداخت موفق و تأییدِ سرور به سرور، وضعیت را به پرداخت‌شده تغییر بده؛ هرگز فقط به بازگشت مرورگر اعتماد نکن.

۲. نمونه با زرین‌پال

آدرس‌ها و فیلدها ممکن است تغییر کنند؛ همیشه با مستندات رسمی زرین‌پال تطبیق بده.

کدZarinpal
// ۱) درخواست
$res = Http::post('https://payment.zarinpal.com/pg/v4/payment/request.json', [
    'merchant_id'  => config('services.zarinpal.merchant'),
    'amount'       => $order->total * 10,   // تومان به ریال، طبق مستندات
    'callback_url' => route('payment.callback', $order),
    'description'  => "سفارش {$order->id}",
])->json('data');

return redirect('https://payment.zarinpal.com/pg/StartPay/'.$res['authority']);

// ۲) Callback و Verify
$verify = Http::post('https://payment.zarinpal.com/pg/v4/payment/verify.json', [
    'merchant_id' => config('services.zarinpal.merchant'),
    'amount'      => $order->total * 10,
    'authority'   => $request->Authority,
])->json('data');

if (($verify['code'] ?? null) == 100) { $order->update(['status' => 'paid']); }

۳. نکات

مبلغ را همیشه از دیتابیس بخوان نه از فرم؛ شناسه‌ی تراکنش را ذخیره کن؛ تأیید را idempotent بنویس تا دوبار اجرا شدن، دوبار سفارش را شارژ نکند.

اشتباه‌های رایج

  1. اعتماد به پارامتر Status در URL بدون Verify.
  2. گرفتن مبلغ از ورودی کاربر.
  3. فراموش‌کردن تبدیل تومان و ریال.
