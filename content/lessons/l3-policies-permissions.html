نقش‌ها و دسترسی‌ها (Policy و Permission)

وقتی نقش‌ها بیش از «ادمین و مشتری» شدند، Policy برای دسترسی به یک رکورد و Permission برای دسترسی به یک کار به‌کار می‌آید.

۱. Policy

کدPolicy
php artisan make:policy PostPolicy --model=Post

// PostPolicy.php
public function update(User $user, Post $post): bool
{
    return $user->id === $post->user_id;
}

// کنترلر
Gate::authorize('update', $post);
// Blade
@can('update', $post) ... @endcan

۲. نقش و دسترسی با Spatie

پکیج رایج برای نقش و دسترسی چندسطحی:

کدSpatie
composer require spatie/laravel-permission
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"
php artisan migrate

// User: use HasRoles;
$user->assignRole('editor');
$user->givePermissionTo('publish posts');
Route::middleware('can:publish posts')->group(...);

۳. تمرین

نقش «ویراستار» بساز که فقط پست‌های خودش را ویرایش کند و «مدیر» که همه را.

اشتباه‌های رایج

  1. بررسی دسترسی فقط در منو و نه در کنترلر؛ همیشه سمت سرور چک کن.
  2. نوشتن شرط نقش‌ها با رشته‌های پراکنده؛ از Permission نام‌دار استفاده کن.
